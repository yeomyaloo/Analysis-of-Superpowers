# 5. 배울 점과 적용할 점

## 프롬프트·에이전트 설계에서 배울 점

1. **목적(why)을 먼저, 절차는 최소로.** 규칙을 덧붙일수록 규칙끼리 조율하는 문장이 본문을 차지한다.
   v6.4.1(2,613단어)은 대부분이 라우팅이었고, v7은 강제 장치를 HARD-GATE와 Builder check 두 개로 줄였다.

2. **열린 질문 > 선택지.** 선택지는 친절해 보이지만 에이전트의 가정을 사람에게 밀어 넣는다(garden-pathing). 사람이 막혔을 때만 메뉴를 준다.

3. **anti-goal을 따로 적는다.** "안 할 것(non-goal)"과 "이러면 동작해도 실패(anti-goal)"를 구분하면 품질 기준이 선명해진다.

4. **대화를 모르는 독자로 검증한다 (Builder check).** 대화를 다 아는 작성자는 문서의 빈칸을 기억으로 메워 못 본다.
   새 컨텍스트의 서브에이전트에게 "계획을 세우려면 뭘 더 물어야 하나?"만 묻는 건 사람의 문서 리뷰에도 그대로 쓸 수 있는 방법이다.

5. **에이전트의 결정은 에이전트의 결정이라고 표시한다.** 기본값을 조용히 고르면 사람은 거부할 기회조차 없다.

6. **승인은 보여 준 것까지만.** "좋네요"를 아직 쓰지 않은 문서·코드에 대한 승인으로 확장하지 않는다.

7. **트리거는 넓게, 진입 비용은 싸게.** 강한 description으로 놓치지 않되, 첫 점검으로 사소한 요청은 즉시 통과시킨다.

8. **원래 의도를 스펙으로 남긴다.** 재작성 스펙 덕분에 "40단어 원본 프롬프트"라는 기준점으로 되돌아갈 수 있었다.

## 인프라·운영 관점에서 배울 점

- **로컬 개발 서버도 인증한다.** 세션 키 + HttpOnly 쿠키 + Origin 검사 + 보안 헤더 + 127.0.0.1 바인드. DNS rebinding까지 고려한다.
- **프로세스 수명을 명시적으로 관리한다.** 소유자 PID 감시 + 유휴 타임아웃 + 상태 파일(`server-info`, `server-stopped`). 고아 프로세스를 남기지 않는다.
- **같은 포트·같은 키로 재시작**해서 클라이언트가 자동 재연결되게 한다 → 쿠버네티스에서 파드 재시작 시 클라이언트 재연결을 설계하는 것과 같은 고민.
- **셸 스크립트의 장애 우회는 주석에 이슈 번호와 함께 남긴다.** `session-start`의 거의 모든 이상한 코드에 "왜"가 붙어 있다.
- **Windows Git Bash 함정:** 백그라운드 프로세스 정리, MSYS2 PID 불일치, EPIPE. bash 스크립트를 Windows에서 돌리는 프로젝트라면 그대로 겪는 문제다.

## ai-judge-platform에 적용해 볼 것

| 아이디어 | 적용 방식 |
|----------|-----------|
| Builder check | 새 ADR을 쓰면 서브에이전트에게 "이 ADR만 읽고 구현 계획을 세울 때 막히는 질문"을 받아 보강 |
| goals / non-goals / anti-goals | `docs/adr/000-template.md`에 anti-goals 항목 추가 검토 |
| 크기 판정 | Stage 작업을 "바로 / 채팅 합의 / 설계 문서(ADR)" 세 크기로 나눠 ADR 남발 방지 |
| 결정 표시 | ADR에 "사용자가 정한 것 / 에이전트가 정한 것"을 구분해 기록 |
| 셸 스크립트 방어 | `scripts/`의 bash가 Git Bash·CI Linux 양쪽에서 돌도록 PATH·EPIPE·heredoc 이슈를 troubleshooting에 정리 |
| 로컬 서버 보안 | 채점기·MCP 서버를 로컬 포트로 띄울 때 127.0.0.1 바인드와 토큰 인증 기본 적용 |
